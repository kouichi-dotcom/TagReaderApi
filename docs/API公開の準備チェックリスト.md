# API 公開の準備チェックリスト（F1 テスト → 本番 B1）

F1 プランで API を公開し、Android に直接インストールしたアプリからアクセスする方法で進めるための確認項目。

## 公開できる状態か：確認結果

### ✅ 問題なく公開できるもの


| 項目                          | 状態  | 補足                                                                                                                                           |
| --------------------------- | --- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **ASP.NET Core Web API 構成** | ✅   | `Program.cs` で CORS・コントローラ・本番時 HTTPS リダイレクトを設定済み。                                                                                            |
| **接続文字列の扱い**                | ✅   | `appsettings.json` には接続文字列を書いていない。接続文字列は `appsettings.Development.json` のみで、`.gitignore` に含まれているためリポジトリにコミットされない。Azure では **環境変数で上書き** する想定。 |
| **本番時の HTTPS**              | ✅   | `if (!app.Environment.IsDevelopment())` で `UseHttpsRedirection()` を有効化済み。                                                                    |
| **.NET バージョン**              | ✅   | net10.0。Azure App Service on Windows では .NET 10 対応済み（プレビュー表記のリージョンあり。GA ロールアウト中）。                                                            |


### ⚠️ 公開前にやること・確認すること


| 項目                              | 内容                                                                                                                                                                                             |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. 接続文字列を Azure で設定**         | Azure の API は **本番DBにのみ接続**する。App Service の **設定 → 環境変数** を開き、**アプリ設定** タブで `ConnectionStrings__DefaultConnection` を追加するか、**接続文字列** タブで `DefaultConnection` を追加し、**本番DB用の接続文字列**を設定する。Azure から自社の本番DBに繋ぐ場合は、Hybrid Connection / VPN 等の接続経路を用意する。 |
| **2. 本番用 appsettings に秘密を書かない** | 接続文字列は **Azure の「アプリの設定」で環境変数として設定** し、リポジトリには入れない。                                                                                                                                            |
| **3. ローカルでビルド確認**               | 公開前に `dotnet build -c Release` および `dotnet publish -c Release -o ./publish` が通ることを確認する。                                                                                                        |
| **4. 料金を発生させないための注意（完全無料で試す場合）** | App Service は **F1（Free）のみ**使用、予算アラート設定、不要なリソースは削除。詳細は [API使用量と料金の見積もり.md](./API使用量と料金の見積もり.md) の「料金を発生させないためにやること」を参照。                                                                                    |

## 公開手順のイメージ（F1）

1. **Azure でリソース作成**
  - リソースグループ作成
  - App Service プラン：**Free F1**（Windows）
  - Web アプリ作成：ランタイム **.NET 10** を選択（または 10 Preview 表記のスタック）
  - **作成ウィザードの他のタブ**: データベース＝**追加しない**、デプロイ＝**なし**（後で ZIP 等でデプロイ）、ネットワーク＝**既定のまま**、監視＝**Application Insights なし**（無料維持）、タグ＝**任意**。最後に「確認および作成」で作成。
2. **接続文字列（本番DB）**
   - App Service → 設定 → **環境変数** → **アプリ設定** タブで「+ 追加」、または **接続文字列** タブで「+ 追加」
   - アプリ設定の場合: 名前 `ConnectionStrings__DefaultConnection`、値に本番DBの接続文字列
   - 接続文字列の場合: 名前 `DefaultConnection`、値に本番DBの接続文字列
   - **適用** で保存（Azure から自社 DB に繋ぐ場合は Hybrid Connection 等の接続先を用意）
3. **発行**
  - Visual Studio: 右クリック発行 → Azure → Azure App Service (Windows) → 対象の Web アプリを選択
  - コマンド: `dotnet publish -c Release` 後、発行フォルダを ZIP でアップロード（Azure ポータル「高度なツール」Kudu や **デプロイ センター** で ZIP デプロイ可能）
4. **アプリの API ベース URL**
  - 発行後の URL 例: `https://<アプリ名>.azurewebsites.net`
  - Flutter アプリの設定でこの URL をベースにし、APK をビルドして直接インストールしてアクセス確認。

## まとめ

- **API は「公開できる状態」**です。接続文字列を Azure の設定で渡すこと、およびローカルで `dotnet build` / `dotnet publish` が通ることを確認すれば、F1 へのデプロイに進めます。
- **方針**: Azure にデプロイした API は **本番DBにのみ接続**する。ローカル開発時のみ、環境（Development / Production）で appsettings を切り替えてローカルDB・本番DBを使い分ける。
- Azure から自社の本番DBに繋ぐ場合は、Hybrid Connection / VPN 等のネットワーク接続の構築が別途必要です。
