# A 案・C 案：アプリ公開までのすべきこと

本番運用パターン（A 案：API のみクラウド / C 案：両方自社）ごとに、**アプリを公開するまでに実施すべきこと**をまとめたチェックリスト。  
詳細な比較・セキュリティ・配布方法は [本番運用パターン比較.md](./本番運用パターン比較.md) を参照。

---

## A 案（API のみクラウド / DB は自社）：公開までのすべきこと

### 1. インフラ・API の準備

| # | すべきこと | 補足 |
|---|------------|------|
| 1 | **Azure サブスクリプション・リソースグループの準備** | 既存があれば流用可。手順は [Azureサブスクリプションとリソースグループの準備.md](./Azureサブスクリプションとリソースグループの準備.md) を参照。 |
| 2 | **Azure App Service の作成** | 本番用の App Service（Windows または Linux）、.NET ランタイム。 |
| 3 | **API のデプロイ** | ビルド・発行し、App Service にデプロイ。本番用の `ASPNETCORE_ENVIRONMENT=Production` を設定。 |
| 4 | **Azure → 自社 DB の接続経路を構築** | **Hybrid Connection**（B1 以上）または **VNet 統合 ＋ Site-to-Site VPN** のいずれかを設計・構築。自社側に Hybrid Connection Manager または VPN ゲートウェイを設置。**当面は本番DBは読み取りのみ**（伝票・担当者・商品の取得のみ。更新は後で有効化）。手順は [Azureから自社DBへの接続経路.md](./Azureから自社DBへの接続経路.md) を参照。 |
| 5 | **接続文字列の設定** | 本番 DB の接続文字列を **Azure Key Vault** または App Service の設定に格納（コードに直書きしない）。 |
| 6 | **HTTPS の有効化** | App Service では標準で HTTPS。独自ドメインを使う場合は証明書をバインド。 |

### 2. セキュリティ

| # | すべきこと | 補足 |
|---|------------|------|
| 7 | **認証の実装（自社のみアクセス可能にする）** | **Google または Microsoft 認証で自社ドメインのみ許可**（推奨）。API でトークン検証・ドメイン制限を実装。 |
| 8 | **CORS の見直し** | 本番では `AllowAnyOrigin()` をやめ、**信頼するオリジンだけ**に限定。 |
| 9 | **レート制限の検討・実装** | 同一ユーザー／IP あたりのリクエスト数制限を API に実装（任意だが推奨）。 |

### 3. アプリ（Flutter）

| # | すべきこと | 補足 |
|---|------------|------|
| 10 | **本番 API の URL を設定** | アプリの設定画面またはビルド設定で、本番の API ベース URL を指定。 |
| 11 | **認証フローの実装** | 起動時または初回に Google / Microsoft でログインし、トークンを取得。API 呼び出し時にトークンを付与。自社ドメイン以外は拒否されることを確認。 |
| 12 | **動作確認** | 本番 API・本番 DB 経由で、担当者取得・商品・伝票など一連の操作ができることを確認。 |

### 4. 配布・公開

| # | すべきこと | 補足 |
|---|------------|------|
| 13 | **Android** | **Google Play：クローズドテスト** で招待リストに社内メールのみ登録。ストアのリンクを社内に共有。開発者登録（約25ドル）が必要。 |
| 14 | **iOS** | **TestFlight** でテスト（90 日以内に仕上げ）→ 安定したら **ABM ＋ カスタム App** に移行。Apple Developer Program（年 $99）が必要。 |

## C 案（API・DB 両方自社）：公開までのすべきこと

### 1. インフラ・API の準備

| # | すべきこと | 補足 |
|---|------------|------|
| 1 | **API を載せるサーバーの準備** | 既存の Windows サーバーまたは新規サーバー。.NET ランタイムをインストール。 |
| 2 | **API の配置** | **IIS の背後で Kestrel** を動かす、または **Kestrel をサービスとして常駐**させる。本番用の `ASPNETCORE_ENVIRONMENT=Production` を設定。 |
| 3 | **DB 接続の設定** | 本番用の接続文字列を設定（環境変数または appsettings.Production.json）。サーバーと DB が同一ネットワーク内にあることを確認。 |
| 4 | **HTTPS の有効化** | IIS で証明書をバインドするか、リバースプロキシ（Nginx 等）で SSL 終端。社内のみの場合は HTTP のみでも可（ポリシーによる）。 |

### 2. VPN（スマホから社内 API にアクセスするため）

| # | すべきこと | 補足 |
|---|------------|------|
| 5 | **VPN ゲートウェイの構築** | オンプレの VPN 機器、または Azure VPN Gateway 等と自社を接続する構成。**スプリットトンネル**で設定（社内向けのみ VPN、他アプリは一般回線）。 |
| 6 | **同時接続ライセンスの確認** | 30〜40 台が同時接続するため、**40 以上**（余裕で 50 など）のライセンスを確保。 |
| 7 | **VPN プロファイル・証明書の準備** | 端末に配布する VPN の設定（プロファイル）と、必要な証明書を準備。 |
| 8 | **30〜40 台への VPN 設定配布** | 各端末に VPN クライアントを設定。手順書の共有、または MDM で配布（MDM 未使用の場合は手動設定）。 |

### 3. セキュリティ

| # | すべきこと | 補足 |
|---|------------|------|
| 9 | **API のアクセス制御** | VPN 経由であれば「VPN にログインできる人＝社内の人」で一括できる。必要に応じて API 側でも認証（従業員コード＋PIN 等）を検討。 |
| 10 | **CORS の見直し** | 本番では信頼するオリジンだけに限定（必要に応じて）。 |

### 4. アプリ（Flutter）

| # | すべきこと | 補足 |
|---|------------|------|
| 11 | **本番 API の URL を設定** | 社内 API の URL（VPN 経由で到達するアドレス）。 |
| 12 | **VPN 未接続時の案内** | 「VPN がオフです。設定で VPN を有効にしてください」などのメッセージと、設定画面を開く導線（任意だが推奨）。 |
| 13 | **動作確認** | VPN 接続後に、本番 API・本番 DB 経由で一連の操作ができることを確認。 |

### 5. 配布・公開

| # | すべきこと | 補足 |
|---|------------|------|
| 14 | **Android** | **Google Play：クローズドテスト** で招待リストに社内メールのみ登録。ストアのリンクを社内に共有。開発者登録（約25ドル）が必要。 |
| 15 | **iOS** | **TestFlight** でテスト（90 日以内に仕上げ）→ 安定したら **ABM ＋ カスタム App** に移行。Apple Developer Program（年 $99）が必要。 |

## 共通：アプリ・配布まわり

どちらの案でも共通で行うとよいこと。

| 項目 | 内容 |
|------|------|
| **開発者アカウント** | **Android**：Google Play 開発者登録（一度 約25ドル）。**iOS**：Apple Developer Program（年 約99ドル）。 |
| **アプリのビルド** | Android は AAB（App Bundle）、iOS は Xcode 経由でアーカイブ・アップロード。 |
| **配布方針** | **Android**：本番は **Google Play クローズドテスト**（MDM 未使用時のおすすめ）。**iOS**：TestFlight（テスト）→ **ABM ＋ カスタム App**（本番）。 |
| **アップデート運用** | Android：Play Console で新バージョンをクローズドテストにリリース。iOS：ABM＋カスタム App の場合は App Store と同様の更新フロー。 |

## 一覧：A 案 vs C 案（公開までにやることの違い）

| カテゴリ | A 案で追加でやること | C 案で追加でやること |
|----------|----------------------|----------------------|
| **インフラ** | Azure App Service、Azure→自社の接続経路（Hybrid Connection 等） | 自社サーバーへの API 配置、VPN ゲートウェイ、端末への VPN 設定配布 |
| **セキュリティ** | 認証（Google/Microsoft 自社ドメイン）、CORS、レート制限 | VPN によるアクセス制御、必要に応じて API 認証 |
| **アプリ** | 本番 API URL、認証フロー実装 | 本番 API URL、VPN 未接続時の案内（推奨） |
| **配布** | Android：Play クローズド / iOS：TestFlight → ABM＋カスタム App（共通） | 同上（共通） |

このドキュメントをチェックリストとして使い、実施した項目に印をつけていくと進捗管理しやすい。
