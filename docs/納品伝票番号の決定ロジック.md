# 納品伝票の「番号」決定ロジック（レガシーPDF基準）

**状態**: 調査メモ（レガシーコード／PDFからの分解）  
**記録日**: 2026-09-11  
**根拠**: PDFに記載のコード（`Reception.cs` 1860～1970行付近の記載あり。ソース未確認の箇所あり）

---

PDFに書かれているコードを基準に、**「どのテーブルの、どのカラムを見て、最終的に納品伝票の番号が決まるか」**まで分解した内容。

## ① まず「この受付で使用しているタグ」を取得する

実行されているSQLは以下の条件。

`tag_table3` と `icタグ台帳` を `tag_id2` で結合している。

| 用途 | テーブル | カラム | 条件・内容 |
| --- | --- | --- | --- |
| 現在の受付を特定 | `tag_table3` | `受付番号` | 画面の `受付番号.Text` と一致 |
| タグを結合 | `tag_table3` | `tag_id2` | `icタグ台帳.tag_id2` と結合 |
| タグを結合 | `icタグ台帳` | `tag_id2` | `tag_table3.tag_id2` と一致 |
| 貸出中か確認 | `icタグ台帳` | `tag_mode2` | `'貸出中'` であること |
| 商品を特定 | `icタグ台帳` | `商品コード` | 後で受付の商品と照合する |
| 納品伝票へ入れる番号 | `icタグ台帳` | `番号` | 最終的に納品明細へ転記 |
| 更新情報 | `icタグ台帳` | `updated` | SELECT対象。ただし今回の番号判定条件には使われていない |

条件としては、

```text
tag_table3.受付番号
    ＝ 現在開いている受付番号

AND

icタグ台帳.tag_mode2
    ＝ "貸出中"
```

つまり、**単にICタグ台帳に番号が存在するだけでは納品伝票には入らない。**

その受付番号と `tag_table3` で紐づいていて、さらに `icタグ台帳` 側で現在「貸出中」である必要がある。

---

## ② `tag_table3` と `icタグ台帳` の関係

```text
tag_table3.tag_id2
        ↓
        ↓ 同じ値
        ↓
icタグ台帳.tag_id2
```

役割としては、

```text
tag_table3
 ├─ 受付番号
 └─ tag_id2
       │
       │ 結合
       ▼
icタグ台帳
 ├─ tag_id2
 ├─ 商品コード
 ├─ tag_mode2
 ├─ 番号
 └─ updated
```

PDFでは、`tag_table3` は**「その受付でどのタグを使用したかを管理する紐付けテーブル」**、`icタグ台帳` は**タグ本体の商品情報や番号を持つマスタ**として説明されている。

---

## ③ 次に「受付の商品」と「タグの商品」を商品コードで照合する

①で取得したタグの中から、

```csharp
ck = tag.Select(
    "商品コード=" + 商品番号.ToString() +
    " and 済=0"
);
```

という判定をしている。

ここでは、

```text
受付の商品明細の商品コード
             ＝
icタグ台帳.商品コード
```

となるタグを探している。

| 比較元 | 場所 | 項目 |
| --- | --- | --- |
| 納品対象の商品 | `goodsGridView` の商品明細 | `商品番号` |
| タグ側の商品 | `icタグ台帳` | `商品コード` |

PDFには、タグと商品明細を直接結び付ける外部キーがないため、**商品コードが実質的な紐付けキーになっている**と記載されている。

```text
icタグ台帳.商品コード
       ↓
       ↓ 一致
       ↓
受付明細の商品番号
```

が番号を付けるための重要な条件。

なお、PDFから確認できるのは `goodsGridView` 上の `商品番号` までで、**その商品番号が元々どのDBテーブルのどのカラムから取得されているかまでは、このPDFには記載されていない。**

---

## ④ 「済=0」も条件になっている

商品コードだけではなく、

```text
済 = 0
```

という条件も付いている。

これは①で取得したタグを処理用のデータ上で、

```text
まだ納品明細に割り当てていない
```

タグだけに絞るためのもの。

ただし注意点として、PDFだけではこの `済` が**SQL Server上のどのテーブルの実カラムなのかは確認できない。**

コードを見る限りでは、

```csharp
tag.Select("商品コード=... and 済=0")
```

となっているので、SQLから取得した後の `tag` という `DataTable` 等に存在する処理用項目である可能性がある。

ここは、元の `Reception.cs` を確認すれば正確に特定できる。

---

## ⑤ 条件に一致したら「icタグ台帳.番号」を納品明細へコピー

一致するタグが見つかると、

```csharp
ndr["tag_id"] = ck[0]["tag_id2"];
ndr["番号"] = ck[0]["番号"];
```

が実行される。

したがって、納品伝票に表示される番号の元データは明確に、

```text
icタグ台帳.番号
```

同時に内部管理用として、

```text
icタグ台帳.tag_id2
    ↓
納品明細.tag_id
```

も設定されている。

| 転記元 | → | 転記先 |
| --- | - | --- |
| `icタグ台帳.tag_id2` | → | 納品明細の `tag_id` |
| **`icタグ台帳.番号`** | → | **納品明細の `番号`** |

ただし、このPDFでは転記先を `ndr["番号"]` として確認できるが、**`ndr` が最終的にSQL Server上のどの納品明細テーブルへ保存されるか、そのテーブル名は記載されていない。**

---

## ⑥ 同じ商品が2台以上あり、それぞれタグが付いている場合

例えば、

```text
受付番号：12345

商品コード：100
台数：3
```

に対して、ICタグ台帳側に

```text
商品コード100
番号 A001

商品コード100
番号 A002

商品コード100
番号 A003
```

の3タグが、この受付で貸出中になっていたとする。

その場合は、

```text
納品明細①
商品コード100
台数 1
番号 A001

納品明細②
商品コード100
台数 1
番号 A002

納品明細③
商品コード100
台数 1
番号 A003
```

というように、**タグの数だけ納品明細を分割する。**

コードでは `ck.Length > 1` の場合に明細行をコピーし、各明細の台数を `1` にしている。

---

## ⑦ 使用済みになったタグは `tag_table3.complete` を更新する

明細に割り当てたタグについては、

```text
tag_table3.complete = 1
```

へ更新している。

これは同じタグを別の明細に重複して使わないための処理。

ここは先ほどの `済=0` と関連している。

PDFから確実に確認できるDB側のカラムは、

```text
tag_table3.complete
```

処理イメージとしては、

```text
未使用
tag_table3.complete = 0
        ↓
納品明細へタグを割り当て
        ↓
使用済
tag_table3.complete = 1
```

ただし、`tag.Select()` の条件に使われている `済` と `tag_table3.complete` がコード上でどのように対応付けされているかまでは、このPDFだけでは断定できない。

---

## ⑧ タグが見つからない場合

次のいずれかを満たさない場合、

```text
① tag_table3.受付番号 が一致

② tag_table3.tag_id2
   ＝ icタグ台帳.tag_id2

③ icタグ台帳.tag_mode2
   ＝ "貸出中"

④ icタグ台帳.商品コード
   ＝ 受付明細の商品番号

⑤ まだ他の納品明細へ割り当てられていない
```

該当するタグが取得できない。

その場合は、

```text
tag_id → 設定しない
番号   → 設定しない
```

となり、受付明細の `台数` だけがそのまま納品明細へコピーされる。

## 全体をDB単位でまとめると

番号が記録される経路は、次のとおり。

```text
【tag_table3】

受付番号
   │
   │ 現在の受付番号と一致
   │
tag_id2
   │
   │ JOIN
   ▼
【icタグ台帳】

tag_id2
商品コード ───── 商品明細の商品番号と一致
tag_mode2  ───── "貸出中"
番号
   │
   │ 条件をすべて満たす
   ▼
【納品明細】

tag_id ← icタグ台帳.tag_id2
番号   ← icタグ台帳.番号
台数   ← 1
```

つまり、**納品伝票の「番号」の直接の取得元は `icタグ台帳.番号`**。

ただし、その番号が納品伝票へ記録されるには、

**`tag_table3.受付番号` → `tag_table3.tag_id2` → `icタグ台帳.tag_id2` → `icタグ台帳.tag_mode2` → `icタグ台帳.商品コード`**

という一連の条件を通過する必要がある。最終的には「受付番号＋商品コード」で対象タグを特定している構造。
