# 本番アーキテクチャ方針（決定）

**決定日**: 2026-08-21  
**状態**: **この構成で進める（採用）**

---

## 採用構成

```
クライアント（Flutter アプリ）
        │ HTTPS
        ▼
Azure App Service
  （ASP.NET Core Web API）
        │ シークレット参照
        ▼
Azure Key Vault
        │
        │ Hybrid Connection 等
        ▼
自社 SQL Server（オンプレ）
```

| 層 | 技術・配置 | 役割 |
|----|------------|------|
| ホスト | **Azure App Service** | API の公開・HTTPS・スケール |
| アプリ | **ASP.NET Core Web API**（TagReaderApi） | 伝票・商品・担当者などの業務 API |
| シークレット | **Azure Key Vault** | DB 接続文字列など秘密情報の保管（コード・リポジトリに直書きしない） |
| データ | **自社 SQL Server** | 既存業務 DB。クラウドへ移行しない |

これは [本番運用パターン比較.md](./本番運用パターン比較.md) の **パターン A（API のみクラウド / DB は自社）** に、Key Vault を必須要素として明示したもの。

---

## 採用理由（要約）

- DB は既存のまま。データ移行不要、社内にデータを残せる
- スマホは VPN なしでインターネット経由の API のみ接続
- .NET API と Azure App Service / Key Vault の親和性が高い
- 月間約 7 万リクエスト規模なら App Service B1 程度で足りる（[API使用量と料金の見積もり.md](./API使用量と料金の見積もり.md)）

クラウドは **Azure**（AWS ではなく）で進める。比較の結論は会話・見積もりドキュメント上の前提と一致。
